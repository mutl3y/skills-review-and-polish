# Skills Review & Polish — Development Patterns & Standards

This file documents proven patterns and standards to follow when working on this project to ensure quality and prevent regressions.

## vscode.lm API Usage (Critical)

### Response Handling Pattern

**Always use `response.stream`, never `response.text`:**

```typescript
// ✅ CORRECT
const response = await model.sendRequest(messages, options, token);
let text = '';
for await (const part of response.stream) {
  let str = '';
  if (typeof part === 'string') {
    str = part;
  } else if (part && typeof part === 'object' && 'value' in part) {
    str = String((part as any).value);
  } else {
    str = String(part);
  }
  text += str;
}
return { text };
```

**Why:** `response.text` applies internal filtering that corrupts JSON output. `response.stream` yields raw structured parts.

**Evidence:** Documented in [docs/VSCODE-LM-STREAMING-FIX.md](docs/VSCODE-LM-STREAMING-FIX.md) — haiku, gpt-5-mini, gpt-4o-mini all failed with response.text corruption.

### Message Format (No System Role)

vscode.lm only accepts `User` role messages. Combine system and user prompts:

```typescript
const combinedPrompt = `${systemPrompt}\n\n${userPrompt}`;
const messages = [vscode.LanguageModelChatMessage.User(combinedPrompt)];
```

### Model Selection (Multi-call Pattern)

Model selection calls `selectChatModels()` three different ways. Mocks must handle all:

```typescript
// Call 1: Initial — all models with pricing
const allModels = await vscode.lm.selectChatModels();

// Call 2: Auto-select — by family
const models = await vscode.lm.selectChatModels({ family: modelId });

// Call 3: User-configured — by ID
const models = await vscode.lm.selectChatModels({ id: modelId });
```

**In tests:** Mock must handle all three patterns or fresh provider instances fail silently.

### Vendor Selection

Always use `copilot` vendor, never `copilotcli`:

```typescript
const preferred = models.find((m) => m.vendor === 'copilot');
if (!preferred) {
  // Error: only copilotcli available, which doesn't work in extensions
  return undefined;
}
```

## Testing Standards

### Cost Guardrails (Hard Requirement)

**All tests involving models MUST use only safe-tier models (≤1x multiplier):**

- ✅ gpt-5-mini (0x)
- ✅ claude-haiku-4.5 (0.33x)
- ✅ claude-sonnet-4.5 (1x)
- ❌ gpt-5.5 (57x) — Never in tests
- ❌ claude-opus (27x) — Never in tests

**Document this constraint in test setup:**

```typescript
/**
 * COST GUARDRAIL: All model-based tests only use safe-tier models (≤1x multiplier).
 * Never test with expensive models (>1x). This prevents accidental budget overruns.
 */
```

### Mock Response Structure

Response objects need BOTH `text` and `stream` properties:

```typescript
mockModel.sendRequest = vi.fn().mockResolvedValue({
  text: jsonString,  // Required for validation check
  stream: (async function* () {
    yield jsonString;  // What complete() actually iterates
  })(),
});
```

### Mock selectChatModels Pattern

```typescript
selectChatModels.mockImplementation((opts) => {
  if (!opts) return Promise.resolve(allModels);      // Initial call
  if (opts?.family === modelId) return Promise.resolve([mockModel]);
  if (opts?.id === modelId) return Promise.resolve([mockModel]);
  return Promise.resolve([]);
});
```

### complete() Return Type

Returns an object, not a string:

```typescript
// ✅ CORRECT
const result = await provider.complete({ systemPrompt, prompt, tier });
expect(result.text).toBe(expectedString);

// ❌ WRONG
expect(result).toBe(expectedString);
```

## TypeScript Configuration

### e2e tsconfig.json Pattern

```json
{
  "extends": "../tsconfig.json",
  "compilerOptions": {
    "rootDir": ".",
    "types": ["node", "playwright/test"]
  },
  "include": ["*.ts"]
}
```

**Key points:**
- Extend parent config (not self-reference)
- Override `rootDir` to allow files outside `src/`
- Include only files in this directory (not `../e2e/**/*`)

## Markdown Standards

### Required Blank Lines

1. **Around lists (MD032)**
   ```markdown
   Paragraph above

   - Item 1
   - Item 2

   Paragraph below
   ```

2. **Around headings (MD022)**
   ```markdown
   Previous paragraph

   ## Heading

   Next paragraph
   ```

3. **Around code blocks (MD031)**
   ```markdown
   Paragraph above

   ```typescript
   code
   ```

   Paragraph below
   ```

### Table Formatting (MD060)

Use spaces around pipes consistently:

```markdown
| Column 1 | Column 2 | Column 3 |
| --- | --- | --- |
| Data     | Data     | Data     |
```

### No Trailing Spaces (MD009)

Remove any spaces at end of lines.

### Common Pitfalls (Quick Reference)

**Don't do these — they break linting:**

- Nested code blocks: Don't show fenced-code syntax inside a code block (use prose instead)
- Heading + list: Always blank line between heading and list
- Regex in inline code: Avoid `` `pattern` `` with leading/trailing spaces
- Trailing punctuation: Headings can't end with `:` or `.`

## Compilation & Linting

### Pre-commit Checklist

Before pushing code:

1. **TypeScript compilation** — `npm run compile`
2. **Lint check** — `npm run lint`
3. **Unit tests** — `npm test`
4. **Markdown lint** — Verify all `.md` files pass linting

### Common Issues & Fixes

| Issue | Cause | Fix |
| --- | --- | --- |
| `Error: ENOENT: no such file or directory` in Playwright tests | Stale compiled .js files with old references | Delete `.js` and `.js.map` files in e2e directory |
| `Circularity detected while resolving configuration` | tsconfig.json extends itself | Change `extends: "./tsconfig.json"` to `extends: "../tsconfig.json"` |
| Model selection returns undefined in tests | Mock doesn't handle all selectChatModels() call patterns | Add all three patterns: no args, by family, by ID |
| `response.stream never yields output` | Using response.text instead | Switch to `response.stream` iteration |
| Markdown lint errors | Missing blank lines around blocks/headings/lists | Add blank lines before and after blocks |

## Code Organization

### Provider Implementation

**Location:** `src/providers/vscodeLmProvider.ts`

Key methods:
- `selectModel(modelId)` — Model selection with cost guardrails
- `complete(request)` — Core LLM request handler
- `parsePricingFromModels()` — Extract pricing from model metadata

Always use the `response.stream` pattern in `complete()`.

### Test Organization

**Location:** `src/providers/vscodeLmProvider.test.ts`

Test structure:
1. Mock setup in `beforeEach` — set up safe-tier models
2. Test model selection — validate guardrails work
3. Test streaming response handling — locked-in regression tests
4. All model tests use safe-tier only

### E2E Tests

**Location:** `e2e/model-picker.test.ts`

Pattern:
1. VS Code authentication setup
2. Wait for extension activation
3. Test UI behavior (command palette, picker, etc.)
4. Tests are UI-focused, not model-focused
